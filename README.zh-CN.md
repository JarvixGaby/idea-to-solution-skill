# Idea to Solution：面向 Codex 的产品发现 Skill

**Idea to Solution 是一个采用产品经理思维的 Codex Skill，用于软件 Idea 评估、JTBD 拆解、产品分析、方案脑暴与 GitHub 开源项目发现。**

[English](README.md)

它帮助个人开发者把粗略的软件想法整理成更清晰的产品方向与复用方案。Skill 采用**产品经理视角**分析早期产品：先理解想法背后的用户工作，再从已有产品中寻找可借鉴的机制，判断是否值得继续探索，并在开发前搜索可以复用的软件。

它面向个人软件项目，不默认把项目当作 SaaS 生意，不要求证明巨大市场，也不假设每项功能都要从头开发。

## 它能帮你做什么

- **明确用户问题。** 梳理谁在什么情境下遇到问题、希望取得什么结果、目前如何解决，以及什么样的首次结果才有用。
- **用产品经理的方法拆 Idea。** 把用户需求和期望结果，与用户最初提出的功能分开；标注事实、假设和待验证问题，避免过早把功能清单当成产品定义。
- **从好产品中学习。** 分析可比产品服务的用户工作、首次价值、核心使用或完成路径、具体体验取舍、成功证据、弱点，以及不能直接照搬的条件。
- **判断是否值得继续探索。** 给出有依据的判断：值得探索、值得但需要缩小切口、证据不足，或当前形态不值得继续。它判断的是下一步是否值得探索，不承诺产品一定成功。
- **探索不同方案。** 比较现成产品、轻量组合、平台原生能力或少量定制工作流。能力拆解用于指导搜索，不意味着每项功能对应一个仓库。
- **寻找可复用的 GitHub 项目。** 优先搜索完整产品和覆盖多项能力的方案，再针对实际缺口寻找组件。依据用户目标和硬约束比较候选，用当前来源核查关键结论，并说明后续还需集成、验证或开发的部分。

## 常见流程

```text
粗略 Idea
    ↓
用户工作、使用情境、约束与假设
    ↓
相关产品案例与可迁移原则
    ↓
继续探索 / 缩小切口 / 补证据 / 暂停
    ↓
不同方案路线与能力覆盖
    ↓
核查 GitHub 候选、缺口与下一步验证
```

流程会根据请求调整：可以只评估 Idea、单独分析一个现成产品、澄清 JTBD，或从明确的 GitHub 搜索需求直接开始。如果 Idea 已形成明确且值得继续的软件方向，Skill 会在同一轮进入方案探索和仓库搜索，除非用户要求在前面阶段停止。

## 搜索结果如何组织

结果围绕**整体方案路线和用户结果**呈现，不强制每项功能配一个仓库。一个项目可能覆盖多个能力；多个项目可能需要集成；官方 API 或更简单的工作流也可能比再引入一个仓库更合适。

对每个重要候选，分析会说明它是什么、为什么适合、哪些证据支持判断、哪些需求尚未覆盖，以及采用后还要做什么。排序优先考虑硬约束和证据，而不是人气。如果没有找到可信候选，会明确说明本轮搜索范围和结果，不会编造推荐。

如果当前环境提供已授权的 GitHub Stars 只读访问能力，可以先检查用户收藏的仓库；否则，或收藏内容无法覆盖目标时，再扩展到公开来源。Skill 会说明访问限制，不声称搜索了全部项目。

## 结构化交付物

完整的 Idea 到方案报告可以包括：

1. **Idea 与 JTBD**：目标用户、使用情境、期望进展、约束和假设。
2. **产品证据**：可比产品、相关机制、证据强度和不可直接复制的部分。
3. **判断**：结论、信心，以及可能改变结论的事实。
4. **方案路线**：能够实现目标的不同方式与取舍。
5. **复用映射**：将整品、多能力项目、组件和平台能力对应到用户结果。
6. **缺口与下一步**：未知事项、需要集成或开发的部分，以及成本最低的有效验证。

默认在对话中结构化呈现。只有用户提出要求时，才生成 Markdown 研究报告或 Coding Handoff。

## 在 Codex 中使用

将仓库安装为个人 Codex Skill：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/JarvixGaby/idea-to-solution-skill.git ~/.codex/skills/idea-to-solution
```

之后可以直接描述粗略想法或提出聚焦请求，例如：

> 我在考虑做一个帮助社区运动俱乐部协调训练时间的轻量工具。值得继续探索吗？有哪些产品机制值得借鉴？现成项目能复用什么？

> 分析 Obsidian 为什么适合个人知识管理，重点看用户工作、首次价值、核心流程和能应用到小型个人工具的设计取舍。

> 找能为 React 应用添加键盘快捷键的 GitHub 库，比较合适的候选，并用证据核对关键约束。

## 使用边界

- Skill 负责**研究与产品发现**，不会安装、克隆、运行候选项目，也不会修改项目代码。
- 结论取决于当前 Codex 环境提供的搜索和阅读工具。无法实时搜索时，会把仓库现状标为未知。
- 仓库描述和文档是待核查的证据，不代表软件已经运行成功或满足所有需求。
- 这是辅助个人探索的工作流，不替代用户研究，也不保证 Idea 一定成功。

## 常见问题

### Idea to Solution 是什么？

这是一个用于产品发现的 Codex Skill：从用户工作出发拆解软件 Idea，探索不同方案路线，再检查现有 GitHub 项目可以复用哪些部分。

### 它会直接开发产品吗？

不会。它负责研究、比较和可选的 Coding Handoff；只有另行明确进入开发步骤时才编写或修改产品代码。

### 它只是 GitHub 仓库搜索工具吗？

不是。它会先明确用户想取得的结果，再比较完整产品、多能力项目、平台能力和更简单的工作流。只有存在值得填补的缺口时，才继续找组件。

### 必须登录 GitHub 才能使用吗？

公开仓库研究不依赖个人 Stars。如果当前环境有已授权的 Stars 只读能力，Skill 可以优先检查收藏项目，并在需要时扩展到公开搜索。
